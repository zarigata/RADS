## 🎯 Scope

### 1. datetime Module ⏰ HIGH PRIORITY

**Purpose:** Complete date/time handling - essential for any real application.

**API Design:**
```rads
import datetime;

// Current time
turbo now = datetime.now();
echo(now.year);    // 2025
echo(now.month);   // 1-12
echo(now.day);     // 1-31
echo(now.hour);    // 0-23
echo(now.minute);  // 0-59
echo(now.second);  // 0-59

// Formatting
turbo formatted = datetime.format(now, "YYYY-MM-DD HH:mm:ss");
echo(formatted);  // "2025-03-01 14:30:45"

// Parsing
turbo parsed = datetime.parse("2025-03-01", "YYYY-MM-DD");

// Unix timestamp
turbo unix = datetime.unix(now);
turbo from_unix = datetime.from_unix(1709251200);

// Date arithmetic
turbo tomorrow = datetime.add(now, days: 1);
turbo next_week = datetime.add(now, days: 7);
turbo last_month = datetime.add(now, months: -1);

// Difference
turbo diff = datetime.diff(now, tomorrow);  // Duration in seconds
```

**Implementation:**
- File: `src/stdlib/stdlib_datetime.c`, `src/stdlib/stdlib_datetime.h`
- Uses: C standard library `<time.h>`
- No external dependencies

**Functions:**
| Function | Description |
|----------|-------------|
| `datetime.now()` | Current timestamp |
| `datetime.format(ts, fmt)` | Format timestamp to string |
| `datetime.parse(str, fmt)` | Parse string to timestamp |
| `datetime.unix(ts)` | Get Unix timestamp |
| `datetime.from_unix(unix)` | Create from Unix timestamp |
| `datetime.add(ts, days, hours, minutes, seconds)` | Add time |
| `datetime.diff(ts1, ts2)` | Time difference in seconds |
| `datetime.year(ts)` | Get year |
| `datetime.month(ts)` | Get month (1-12) |
| `datetime.day(ts)` | Get day |
| `datetime.hour(ts)` | Get hour |
| `datetime.minute(ts)` | Get minute |
| `datetime.second(ts)` | Get second |

### 2. regex Module 🔍 HIGH PRIORITY

**Purpose:** Pattern matching and text manipulation - critical for validation, parsing, and data extraction.

**API Design:**
```rads
import regex;

// Compile pattern (cached)
turbo pattern = regex.compile("\\d+");

// Test match
if (regex.match(pattern, "123")) {
    echo("Found numbers!");
}

// Find all matches
turbo matches = regex.findall(pattern, "abc123def456");
// matches = ["123", "456"]

// Search for first match
turbo result = regex.search(pattern, "price: 99 dollars");
// result = { match: "99", start: 7, end: 9 }

// Replace
turbo replaced = regex.replace(pattern, "item123", "X");
// replaced = "itemX"

// Split by pattern
turbo parts = regex.split(pattern, "a1b2c3");
// parts = ["a", "b", "c"]
```

**Implementation:**
- File: `src/stdlib/stdlib_regex.c`, `src/stdlib/stdlib_regex.h`
- Uses: POSIX regex (`<regex.h>`)
- No external dependencies (standard on Linux/macOS)

**Functions:**
| Function | Description |
|----------|-------------|
| `regex.compile(pattern)` | Compile regex pattern |
| `regex.match(regex, str)` | Boolean: does pattern match? |
| `regex.findall(regex, str)` | Array of all matches |
| `regex.search(regex, str)` | First match with position |
| `regex.replace(regex, str, replacement)` | Replace matches |
| `regex.split(regex, str)` | Split by pattern |

### 3. Test Framework 🧪 HIGH PRIORITY

**Purpose:** Built-in testing - no more manual `if` statements and `echo`.

**API Design:**
```rads
import test;

test.describe("Math operations", blast() {
    test.it("should add correctly", blast() {
        test.expect(1 + 1).toBe(2);
        test.expect(2 + 2).toBe(4);
    });
    
    test.it("should multiply correctly", blast() {
        test.expect(3 * 3).toBe(9);
    });
    
    test.it("should handle negative numbers", blast() {
        test.expect(-5 + 5).toBe(0);
    });
});

test.describe("String operations", blast() {
    test.it("should concatenate", blast() {
        test.expect("hello" + " world").toBe("hello world");
    });
    
    test.it("should check length", blast() {
        test.expect(length("test")).toBe(4);
    });
});

// Run all tests
test.run();
```

**Output:**
```
✓ Math operations
  ✓ should add correctly (2 assertions)
  ✓ should multiply correctly
  ✓ should handle negative numbers
✓ String operations
  ✓ should concatenate
  ✓ should check length

Tests: 5 passed, 5 total
Assertions: 6 passed, 6 total
```

**Implementation:**
- File: `src/stdlib/stdlib_test.c`, `src/stdlib/stdlib_test.h`
- Stateful: Tracks test suites, test cases, assertions
- Global test registry

**Functions:**
| Function | Description |
|----------|-------------|
| `test.describe(name, fn)` | Define test suite |
| `test.it(name, fn)` | Define test case |
| `test.expect(value)` | Create assertion |
| `test.expect(val).toBe(expected)` | Strict equality |
| `test.expect(val).toEqual(expected)` | Deep equality |
| `test.expect(val).toBeTruthy()` | Truthy check |
| `test.expect(val).toBeFalsy()` | Falsy check |
| `test.expect(val).toBeNull()` | Null check |
| `test.expect(fn).toThrow()` | Exception check |
| `test.run()` | Execute all tests |
| `test.skip(name, fn)` | Skip test |
| `test.only(name, fn)` | Run only this test |
| `test.beforeEach(fn)` | Setup before each test |
| `test.afterEach(fn)` | Cleanup after each test |

## 🔧 Implementation Details

### datetime Module

```c
// stdlib_datetime.h
#ifndef STDLIB_DATETIME_H
#define STDLIB_DATETIME_H

#include "../core/interpreter.h"

void stdlib_datetime_register(Interpreter* interp);

#endif
```

**Key Implementation Notes:**
- Return struct with year, month, day, hour, minute, second
- Format string parsing: YYYY, MM, DD, HH, mm, ss
- Use `struct tm` and `time_t` from `<time.h>`
- Thread-safe: no global state

### regex Module

```c
// stdlib_regex.h
#ifndef STDLIB_REGEX_H
#define STDLIB_REGEX_H

#include "../core/interpreter.h"

void stdlib_regex_register(Interpreter* interp);

#endif
```

**Key Implementation Notes:**
- Cache compiled patterns in registry
- Return array for `findall`
- Return struct for `search` (match, start, end)
- Handle regex compilation errors gracefully
- Use POSIX extended regex: `REG_EXTENDED`

## 🎯 Rationale

### Why These Three?

1. **datetime** - Every application needs timestamps. Logging, scheduling, file operations, user sessions, analytics - impossible to build real applications without date/time handling.

2. **regex** - Text processing is fundamental. Validation (email, phone), parsing (logs, data), extraction - manual string operations are tedious and error-prone.

3. **test framework** - Developer experience. No real project ships without tests. Manual `if` statements don't scale. A proper test framework makes RADS a serious development language.

### Why Not Other Features?

- **JIT/LLVM** - Requires LLVM dependency, significant complexity, current bytecode VM is fast enough for most use cases
- **Generics** - Type system overhaul, better for v0.1.0
- **Pattern Matching** - Parser/interpreter changes, deferred
- **Windows Support** - Platform work, deferred
